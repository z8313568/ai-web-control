# 网站适配（拾取配置工具）

本扩展不写死任何网站选择器。你可以为**任意大模型网页**（内网/公网都行）配置
输入框、发送按钮、输出区域的选择器。配置好后扩展自动按它监听和注入提示词。

DeepSeek 开箱即用（内置默认配置），其他网站用拾取工具配置。

## 快速适配一个新网站

假设你在内网部署了一个 AI 聊天网页 `http://10.0.0.5:8080`：

1. 打开该网页，让对话框可见
2. 点扩展图标打开侧边栏 → 切到「**网站配置**」标签
3. 点「**🟦 在当前页面拾取**」
4. Chrome 弹出权限框「允许扩展读写 10.0.0.5:8080」→ 点允许
5. 网页顶部出现拾取浮条：
   - **鼠标悬停**到输入框 → 红框高亮，浮条显示候选选择器
   - 点「**设为输入框**」
6. 同样操作：悬停到发送按钮 → 点「设为发送按钮」
7. 悬停到 AI 回复的区域 → 点「**设为输出区域**」（这是监听 webctl 的关键）
8. 点「**完成保存**」（或按 Esc）

完成。扩展现在会监听该网页的 AI 输出，捕获 webctl 工具调用并执行。

## 选择器生成策略

拾取工具自动按稳定性优先级生成选择器，你通常不用手写：

| 优先级 | 来源 | 示例 | 稳定性 |
|---|---|---|---|
| 1 | `id` | `#chat-input` | 最稳 |
| 2 | `data-testid` / `data-role` | `div[data-role="assistant"]` | 很稳 |
| 3 | `aria-label` | `button[aria-label*="发送"]` | 较稳 |
| 4 | `placeholder` | `textarea[placeholder*="发送"]` | 较稳 |
| 5 | 稳定 class（过滤掉哈希） | `div.ds-markdown.content` | 中等 |
| 6 | nth-of-type 路径 | `div:nth-of-type(2) > p` | 兜底，较脆 |

哈希类名（如 `_27c9245`、`css-1a2b3c`）会被自动过滤掉——它们每次构建都会变。

## 测试选择器

不确定某个选择器对不对？在「网站配置」标签的「测试选择器」框里输入，点「测试」，
会显示当前页面匹配到几个元素。匹配 0 说明选择器写错了或元素不存在。

## 手动编辑配置

点「手动添加/编辑」，直接填 JSON：

```json
{
  "host": "10.0.0.5:8080",
  "label": "内网 AI",
  "input": "#chat-input",
  "output": ".assistant-reply",
  "send": "#send-btn",
  "injectPrompt": true
}
```
- `host`：域名（含端口，不含协议和路径），必填
- `input` / `output` / `send`：CSS 选择器。`output` 必填（监听必需），其余可选
- `injectPrompt`：是否在新对话自动填入系统提示词，默认 true

## 配置存在哪

`chrome.storage.local` 的 `adapters` 键，按 host 分组。卸载扩展会丢失，建议重要配置备份。

## 重新生效

- 改完配置（拾取保存或手动编辑），扩展会自动给已打开的同域名标签页重新注入适配器
- 如果没生效，点「**重载当前页适配器**」强制重注入
- 或刷新该网页（标签页加载完成时扩展会自动按配置注入）

## 内置默认网站

目前内置：`chat.deepseek.com`。加载扩展后该网站自动可用，无需配置。
在 `extension/content/config.js` 的 `DEFAULT_ADAPTERS` 里可加更多默认网站。

## 常见问题

**Q：拾取时选错了元素怎么办？**
A：再悬停到正确元素，点对应按钮重新设一次即可覆盖。最后点「完成保存」。

**Q：网页改版后选择器失效了？**
A：重新拾取一次。或用「测试选择器」先确认哪个选择器坏了，针对性修。

**Q：AI 输出的 webctl 块没被捕获？**
A：多半是 `output` 选择器没框住 AI 回复正文。用「测试选择器」验证：输入你的 output 选择器，
应该匹配到≥1个元素。若匹配 0，重新拾取输出区域。

**Q：内网网站是 IP 地址（如 192.168.1.10），能配置吗？**
A：能。host 字段填 `192.168.1.10` 或 `192.168.1.10:8080`（带端口）。
